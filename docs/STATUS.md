The remaining gap is **client-side**: a reconciliation rule (detect the flip against the served catalog, prompt/strip before POSTing). Sharper now that the structured `{ errors[] }` `path` identifies the offending activity, though a stable error-`code` enum is still wanted (below). — grill Q2 #2 + ADR-0005 atomicity.
- **`GET /api/v1/metrics` route — unpinned (needs ADR-0006).** The catalog **data** now exists server-side (`src/weather/metricCatalog.js`, live vs coming-soon), but the **route** (response envelope, error shape, per-region availability, refresh/TTL) is in no ADR. **No longer blocks the #5b authoring metric-picker** (decided 2026-07-12): #5b ships a **client-side static catalog behind a `MetricCatalogProviding` swap seam** (a hand-mirror of the LIVE set in `metricCatalog.js`), so a `RemoteMetricCatalog` conformer drops in with zero call-site changes when the route lands. Route still **deferred (cleanly parallel — see §5)**; it would read from the existing `metricCatalog.js`. — grill Q2(a)/Q7 + 2026-06-20 audit.
- **#5b/Phase-2 prerequisites surfaced by the 2026-06-20 audit (none block #5a-core):** (a) **ADR-0005 error-`code` enum** — error messages are English prose; the atomic metric-flip recovery needs stable codes for the client to find the offending activity; (b) **seed Template threshold values** — the onboarding seed activities' actual numbers are unpinned (needed once the client authors/POSTs). Both ride with authoring/Phase-2, not #5a-core. *(2026-07-12: the #5b spec's LIVE-only picker makes an in-app-authored activity unable to trigger the metric-flip 400 at all, so the error-`code` enum (a) is a nice-to-have for #5b, not a hard prerequisite; seed thresholds (b) stay provisional and are pinned during the #5b build.)*
- **Grill-only open items (design, not yet folded elsewhere):** (a) **v1-vs-fast-follow launch sequencing** — what ships at first launch vs fast-follow was never decided (grill PENDING #2); (b) **Template-override + client sync schemas** — the custom-activity *request* schema is built ([ADR-0005](adr/0005-custom-activity-request-schema.md)), but the Template-derived override representation and the iCloud/anon-device sync model are still undesigned (grill PENDING #1 remainder, distinct from the client stale-activity reconciliation above).
