## Goal

Every entry in every activity's `days[]` gains one additive wire field: `score` — integer `1..100` or `null` — computed in the decision module per [ADR-0011](../../adr/0011-day-score.md). Nothing else on the wire changes.

## Hard constraints

- `validateRatingRequest` / `validateActivities`: **untouched**. The request shape does not change.
- `src/weather/**`: untouched. `src/routes/**`: no logic changes (the route already passes engine output through; only if the route re-shapes `days[]` keys does it need to carry `score` — check `rating.js` before assuming).
- The score **never feeds** `rating`, the digest, or the Perfect-window detector — jobs ignore it (ADR-0011 independence rule). No changes under `src/jobs/` or `src/notifications/`.
- No new dependencies.
- Per-day key order on the wire: `dayIndex`, `rating`, (`startIndex`, `endIndex`, `duration` when rated), `score` — **`score` last, present on every day object** (number, or `null` per the null rule).

## The formula (ADR-0011, condensed — the ADR text is normative)

Per hour, per **thresholded** metric (display-only metrics never contribute):
- Two-sided band (`min`+`max`): linear, `0` at either edge → `100` at centre; outside → `0`.
- One-sided (`min`-only / `max`-only): binary — `100` inside, `0` outside.
- Flag (`forbidTrue`): `false` → `100`, `true` → `0`.
- `null`/missing value → `0` (B2 posture: absent data fails).
- Any **required** threshold failing → the whole hour scores `0`.

Hour score = mean over thresholded metrics. Day score = mean over the bucket's window hours → round to nearest integer → clamp to `1..100`. `score: null` **iff** the bucket contains zero window hours (verify how such day entries arise in `evaluateAll` — e.g. a day-0 whose same-day window is entirely before the forecast start — and pin it with a test; if they cannot arise, prove it with a test and note it here).

**Open question — resolved.** Zero-window-hour buckets arise from exactly one reachable branch: `bucketSameDayWindow`, whose `kept` array is empty whenever no hour of a calendar day has `localHour ∈ [startHour, endHour)` — concretely a **partial day-0 whose window is already past the forecast start** (pinned: an 18:00-local start against a `[9,17)` window → `days[0]` is `{ rating: null, score: null }`), and symmetrically a provider-truncated tail day. `bucketByLocalDay` can never produce one (each bucket is created *from* an hour). `bucketNightWindow`'s `|| { offset: 0, hours: [] }` gap fallback is **defensive but unreachable** — contiguous hours cannot skip a night ordinal between `0` and `maxNight` — so it is noted, not pinned as a live path. Note also that `evaluate([])` already returns `{ rating: null }`, so the empty bucket's `rating` was always `null`; only `score` distinguishes it (`null`) from a day whose hours all failed (clamped `1`).
